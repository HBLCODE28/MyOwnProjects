# תאר אותי - MVP 0.4.9

אתר Mobile-first בעברית ו-RTL למשחק "תאר אותי".

## טכנולוגיה

- Next.js + React + TypeScript
- Socket.IO לסנכרון בזמן אמת
- Node.js custom server שמחזיק את מצב המשחק בצד השרת
- PWA / Fullscreen למובייל
- אייקוני Avatar אחידים מ-SVG Repo; כל הטקסט באתר נשאר Arial

מצב המשחק נשמר בזיכרון תהליך ה-Node. אין Local Storage ואין שמירה של המילה שנאמרת בקול. הפעלה מחדש של השרת מוחקת חדרים פעילים.

## מה ממומש

- יצירת חדר וקוד כניסה אקראי של 8 תווים (כ-40 ביט), ללא I/O/0/1 כדי לצמצם טעויות הקלדה
- הגבלת ניסיונות של קוד חדר שגוי: לאחר 8 ניסיונות שגויים בתוך דקה ההצטרפות הידנית נחסמת זמנית
- שיתוף הזמנה דרך כפתור "שתף משחק" בלי להציג את ה-URL בממשק, עם הודעת הזמנה קצרה ואימוג'ים ליד הקישור
- בטלפון, כאשר Web Share זמין, הכפתור פותח את חלון השיתוף של המכשיר; ב-HTTP מקומי או בדפדפן ללא Web Share ההזמנה מועתקת ללוח
- הצטרפות ללא חשבון
- משחק יכול להתחיל רק כאשר יש לפחות 4 משתתפים מחוברים בחדר
- QR חזר ללובי המארגן ומוצג גם במחשב וגם בטלפון; הוא מפנה ישירות לקישור ההזמנה
- הזנת קוד חדר במובייל גוללת את השדה לאזור הגלוי ומוסיפה מרווח מול המקלדת כדי שהקוד לא יוסתר
- כותרת הלובי ממורכזת
- אפשרות QA הוסרה לחלוטין מהממשק ומהשרת
- פריסת Desktop צומצמה למשטח של כ-1080x760 לכל היותר, שמתאים בנוחות למסך 1920x1080
- בחירת דמות עקבית מתוך דמויות נשים, גברים, ילדים ומבוגרים
- המארגן מופיע ברשימת המשתתפים ומשתתף במשחק
- Browser session באמצעות cookie מסוג HttpOnly: רענון או טאב נוסף באותו דפדפן מתחברים לאותו participant ולא יוצרים כפילות
- מניעת שמות כפולים בחדר
- בחירת מספר סבבים עם מגבלת n-1 ו-Popup שמסביר למה אי אפשר לעבור את המגבלה
- שיבוץ יעד שונה לכל משתתף בכל סבב
- מניעת חזרה על אותו זוג מתאר -> יעד, עם fallback אם אין פתרון
- שלב הכנה של 60 שניות
- כל משתתף יכול ללחוץ "התחל משחק"; כאשר כולם מוכנים המשחק מתקדם מיד
- תורים אוטומטיים של 10 שניות
- אם כל המשתתפים הזכאים לנחש כבר בחרו לפני סוף הטיימר, התור נסגר מיד ועוברים אוטומטית לתור הבא
- בכל מעבר לתור חדש נשמע אצל המארגן בלבד ג'ינגל קצר; אצל המשתתפים אין צליל מעבר
- ניחוש מכל המכשירים, כולל אפשרות ליעד לנחש את עצמו
- שם שכבר נבחר מוסר מאפשרויות הניחוש של אותו משתמש להמשך הסבב
- היעד האישי של המשתמש נשאר מוצג ברשימת הניחוש אך חסום ללחיצה, ללא תווית שמסבירה למה
- המשתתף שמתאר כרגע נשאר מוצג ברשימת הניחוש אך חסום ללחיצה, וגם השרת דוחה ניסיון לבחור בו
- אם נשארת אפשרות חוקית אחת בלבד, השרת בוחר אותה אוטומטית ומציג למשתמש הודעה קצרה
- Fastest finger: רק הניחוש הנכון הראשון מקבל נקודות
- ניקוד: מנחש ראשון +2, מתאר +1 אם ניחשו, מתאר +3 אם לא ניחשו
- חשיפת התשובות רק בסוף הסבב
- טבלת ניקוד סבבית ומצטברת
- מסך סיום עם Leaderboard, כל הזיווגים ומפת חברויות
- בסיום המשחק המארגן יכול ליצור משחק חדש עם אותם משתתפים; כולם חוזרים יחד ללובי והניקוד והזיווגים מתאפסים
- התראת ניתוק נשלחת למארגן מיד כאשר Socket.IO מזהה שמשתתף התנתק; heartbeat מהיר יותר מקצר גם זיהוי של ניתוק רשת שקט
- אם המארגן מתנתק, כל המשתתפים רואים התראה. אם הוא לא חוזר בתוך 10 שניות, הניהול עובר למשתתף המחובר הבא לפי סדר ההצטרפות והחדר נשאר פעיל
- Fullscreen אוטומטי ככל שהדפדפן מאפשר
- פונט אחיד בכל האתר, במובייל וב-Desktop: Arial עם fallback ל-Helvetica

## הרצה מקומית

דרישות: Node.js 20.9 ומעלה ו-npm.

הדרך הפשוטה ב-Windows היא ללחוץ פעמיים על:

```text
START_TAER_OTI.bat
```

או ידנית:

```cmd
npm install
npm run dev
```

במחשב:

```text
http://localhost:3000
```

כדי לפתוח מטלפון באותה רשת Wi-Fi:

```cmd
ipconfig
```

ואז פתחו את כתובת ה-IPv4 של המחשב, לדוגמה:

```text
http://10.100.102.16:3000
```

## משתמשי בדיקה מקומיים ללא כפתור QA

כלי הבדיקה נמצא מחוץ לאתר ואינו מוסיף endpoint או כפתור QA לממשק.

1. הפעילו את השרת עם `START_TAER_OTI.bat`.
2. צרו חדר רגיל באתר והעתיקו את קוד החדר.
3. הפעילו `ADD_TEST_PLAYERS.bat`.
4. הזינו את קוד החדר ואת מספר משתמשי הבדיקה. ברירת המחדל היא 3 - יחד עם המארגן מתקבלים 4 משתתפים, המינימום למשחק.
5. השאירו את חלון ה-BAT פתוח. משתמשי הבדיקה יסמנו מוכנות וינחשו שמות אקראיים. `Ctrl+C` מנתק אותם.

אפשר גם דרך CMD:

```cmd
npm run test:players -- 7Q3K9M2R 3 http://localhost:3000
```

הכלי מסכים להתחבר רק ל-`localhost` או לכתובת פרטית ברשת המקומית, כגון `10.x.x.x` או `192.168.x.x`.

## בדיקות דרך CMD

בדיקות מנוע, קישורים ו-Socket.IO:

```cmd
npm test
```

בדיקה עמוקה הכוללת TypeScript, כל הבדיקות ו-production build:

```cmd
npm run test:deep
```

בדיקה של שרת שכבר רץ דרך כתובת הרשת האמיתית:

```cmd
npm run test:live -- http://10.100.102.16:3000
```

הבדיקות כוללות בין היתר:

- שיבוצים ללא שיבוץ עצמי וללא חזרות
- קישורי הזמנה ושינוי token זדוני
- הופעת המארגן בלובי
- הצטרפות בזמן אמת ועדכון מסך המארגן
- reconnect וטאב נוסף
- browser session שלא יוצר participant נוסף באותו חדר
- קיצור שלב ההכנה כאשר כולם מוכנים
- איפוס משחק חדש והחזרת כל המשתתפים ללובי
- הסרת שם שכבר נבחר מאפשרויות הניחוש
- בחירה אוטומטית כאשר נשאר יעד חוקי יחיד
- התראת ניתוק מיידית ברמת מצב החדר
- העברת ניהול אוטומטית למשתתף הבא אם המארגן לא חוזר בתוך חלון ה-reconnect

## Session ו-Reconnect

השרת מנפיק cookie אקראי מסוג `HttpOnly`, `SameSite=Strict` עם תוקף של עד 6 שעות. ה-cookie אינו נגיש ל-JavaScript. כל participant בחדר משויך ל-browser session הזה, ולכן refresh או טאב נוסף באותו דפדפן מתחברים לאותה זהות.

בנוסף קיים resume token ב-URL fragment כ-fallback. ה-fragment אינו נשלח בבקשת HTTP ואינו מופיע ב-Referer רגיל.

בלי הרשמה או חשבון אי אפשר לזהות באופן אמין שאותו אדם נכנס ממכשיר אחר או מדפדפן אחר. מניעת הכפילות היא ברמת אותו browser session, ובנוסף שמות זהים נחסמים בחדר.

## אבטחת ההזמנה

- קישור ההזמנה מכיל token אקראי של 256 ביט במקום להסתמך רק על קוד החדר הקצר.
- ה-token אינו מוצג כטקסט בממשק המארגן.
- ה-token מתחלף ביצירת משחק חדש.
- Socket.IO בודק Same-Origin.
- השרת שולח כותרות אבטחה בסיסיות.
- לפריסה אמיתית באינטרנט יש להשתמש ב-HTTPS. כתובת `http://10.x.x.x:3000` מיועדת לפיתוח ברשת מקומית ואינה מוצפנת.

## שיתוף בטלפון

Web Share API דורש בדרך כלל secure context. בפריסה עם HTTPS, "שתף משחק" פותח את חלון השיתוף של הטלפון וניתן לבחור WhatsApp, Telegram, SMS וכו'. בהרצה מקומית דרך `http://<LAN-IP>:3000`, אם הדפדפן לא מאפשר Web Share, הטקסט והקישור מועתקים ללוח במקום להציג URL על המסך.

## Fullscreen

Chrome ודפדפנים אחרים אינם מאפשרים לאתר להיכנס ל-Fullscreen בזמן טעינת העמוד ללא פעולה של המשתמש. לכן במובייל הבקשה מתבצעת בפעולת המשתמש הראשונה ובכפתורי הפעולה המרכזיים. ב-iPhone הדרך היציבה להסיר את ממשק Safari היא Add to Home Screen ולהפעיל את ה-PWA מהאייקון.

## Build לפרודקשן

```cmd
npm run build
npm start
```

לפרודקשן מרובה שרתים יש להעביר את Game State מ-memory ל-Redis. אם רוצים לשמור היסטוריית משחקים, אפשר להוסיף PostgreSQL/Supabase.

## Windows - הפעלה אוטומטית

`START_TAER_OTI.bat`:

- בודק ש-Node.js ו-npm זמינים
- מזהה את כתובת ה-IPv4 המקומית ומציג את הכתובת לפתיחה מהטלפון
- מריץ `npm install --audit=false` רק אם `node_modules` עדיין לא קיים או שחבילת ה-QR חסרה
- מפעיל `npm run dev`

ה-BAT אינו מריץ בדיקות, audit או תיקוני `--force`.

## Changes in 0.5.0

- A turn is not skipped when all remaining guesses were auto-filled at the start of that turn; the describer still gets the full 10-second turn.
- Turn order is reshuffled every round and is guaranteed not to be identical to the previous round.
